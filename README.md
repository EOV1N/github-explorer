# GitHub Explorer

Веб-приложение для поиска публичных репозиториев GitHub через официальный REST API.
React + TypeScript, асинхронные запросы с отменой, управление состоянием без сторонних сторов, localStorage, тесты Vitest.

## Технологии

- **React 19 + TypeScript + Vite 7**
- **Tailwind CSS 4** — только утилиты для раскладки и отступов; вся цветовая система
  и темы собраны вручную на CSS-переменных (никаких готовых UI-компонентов)
- **Lucide** — иконки
- **Vitest + jsdom** — юнит-тесты логики
- **GitHub REST API** — endpoint `GET /search/repositories`

## Возможности

- Живой поиск с debounce (450 мс), запуск по Enter и кнопкой, подсказка по `/`
- Отмена предыдущего запроса при новом (`AbortController`) и защита от гонок
  (устаревшие ответы отбрасываются по request-id)
- Карточки: владелец и аватар, описание, язык, звёзды, форки, дата обновления,
  топики; ссылки открываются в новой вкладке (`rel="noopener noreferrer"`)
- Сортировка: лучшее совпадение / звёзды / дата обновления (на стороне API)
- Фильтрация по языку среди загруженных результатов, общий счётчик `total_count`
- Пагинация «Загрузить ещё» (`page` / `per_page`), дедупликация по `id`,
  сброс страницы при новом поиске
- Избранное: добавление/удаление, отдельный вид, хранение в `localStorage`
  с валидацией и восстановлением после перезагрузки
- Все состояния UI: стартовая подсказка, skeleton-загрузка, успех, «ничего не
  найдено», ошибка сети, rate-limit (с временем сброса), ошибка валидации запроса
- Светлая и тёмная темы (по умолчанию — системная), сохранение выбора
- Адаптивная вёрстка, `prefers-reduced-motion`, фокус-кольца, aria-атрибуты
- Deep-link: `/?q=react` — запрос можно сохранить или переслать

## Требования

- Node.js 18+ (рекомендуется 20+)
- npm 9+

## Установка и запуск

```bash
npm install        # установка зависимостей
npm run dev        # dev-сервер (Vite)
npm run build      # production-сборка в dist/
npm run preview    # локальный просмотр production-сборки
npm run test       # юнит-тесты (Vitest, однократный прогон)
npm run test:watch # тесты в watch-режиме
```

Скрипт `scripts/screenshot.mjs` обновляет скриншот из README
(требуется `npx playwright install chromium` и запущенный `npm run preview`).

## Особенности GitHub API

- Поиск **без токена** ограничен ~**10 запросами в минуту** (и 60 запросами/мин
  для остальных endpoint'ов). При исчерпании лимита API отвечает `403` (иногда
  `429`) c заголовками `X-RateLimit-Remaining` / `X-RateLimit-Reset` — приложение
  показывает понятное сообщение и время сброса, **без** автоматических повторов.
- Для любого поиска GitHub отдаёт **не более первых 1000 результатов**
  (`page × per_page ≤ 1000`) — кнопка «Загрузить ещё» корректно останавливается.
- `422 Unprocessable Entity` означает некорректный запрос (пустые квалификаторы
  и т.п.) — текст ошибки от GitHub показывается пользователю.
- HTTP-статус проверяется до разбора тела ответа; `AbortError` обрабатывается
  отдельно и никогда не отображается как ошибка.

## Известные ограничения

- Фильтр по языку применяется только к **уже загруженным** результатам —
  GitHub Search API не позволяет комбинировать произвольный запрос пользователя
  с надёжной серверной фильтрацией по списку языков без изменения запроса.
- Избранное — это снапшот карточки на момент добавления; счётчики звёзд
  не обновляются автоматически (REST API не имеет подписок).
- Поддерживается только неаутентифицированный доступ: токен не хранится
  в исходниках и не требуется для работы.
- В избранном карточка удаляется сразу, без undo.

## Тестирование

30 юнит-тестов (Vitest + jsdom) покрывают наиболее хрупкую логику:

- форматирование чисел и дат (`formatters.test.ts`)
- добавление/удаление избранного, дедупликация, иммутабельность
  (`favoritesStorage.test.ts`)
- устойчивость к повреждённым данным в `localStorage`
- маппинг ошибок API: rate-limit (403/429 + reset), валидация (422), сеть,
  прочие HTTP-статусы, нестандартный payload, проброс `AbortError`
  (`githubApi.test.ts`, `fetch` мокается через `vi.stubGlobal`)
